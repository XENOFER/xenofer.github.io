Race Conditions in Windows LPE

Notes from studying a Windows Defender privilege-escalation PoC. The bug is a classic TOCTOU (time-of-check to time-of-use) race.

The window

Two operations that should be atomic aren't:

  1. A privileged service checks a path.
  2. A moment later it uses that path.

Between the two, an attacker swaps the target — winning the race lands code execution as SYSTEM.

Why success varies

Factor Effect
CPU cores more cores widen the window
Disk speed slower I/O widens the window
Scheduling noisy systems are less predictable 
check  ──►  [ attacker swaps target ]  ──►  use
                    ▲ win here

Open question

Could the race be made deterministic with an oplock to freeze the file operation at the right instant?

This is an analysis of public research, not an original discovery.
