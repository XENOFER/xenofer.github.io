Breaking JWTs: alg:none and weak secrets

JSON Web Tokens are everywhere in modern auth — and they fail in a handful of predictable ways. Here are two classics, both demonstrated live in CipherToken.

1. The alg:none forgery

A JWT header declares its signing algorithm. If a server trusts that field blindly, an attacker can set it to none, drop the signature, and forge any payload:

{ "alg": "none", "typ": "JWT" }

Fix: pin the expected algorithm server-side; never let the token choose it.

2. Weak HMAC secrets

HS256 signs with a shared secret. A short or guessable secret can be brute-forced offline against a captured token:

hashcat -a 0 -m 16500 token.jwt wordlist.txt

Fix: use long, random secrets (32+ bytes), or move to RS256/ES256.

Takeaway

Treat the token header as attacker-controlled. Validate algorithm and signature on every request.
